# Публикация LUMO через GitHub Pages

## Что подготовлено в проекте

- `vite.config.ts` автоматически определяет имя репозитория из `GITHUB_REPOSITORY` в GitHub Actions и выставляет правильный `base` для URL вида `https://<owner>.github.io/<repo>/`.
- Для локального запуска и GitHub user-site (`<owner>.github.io`) используется корневой путь `/`.
- `vite-plugin-pwa` получает тот же base path; `start_url` и `scope` манифеста относительные (`./`).
- SVG-стикеры перенесены из `public` в `src/assets/stickers`, чтобы Vite переписывал пути с учётом base path и включал их в сборку. После переноса удали старую папку `public/stickers`, если она осталась в твоей рабочей копии.
- Workflow `.github/workflows/deploy.yml` выполняет `npm ci`, `npm run build` и публикует `dist` через GitHub Pages.
- `package-lock.json` добавлен для воспроизводимой установки зависимостей.

## Перед публикацией: безопасность публичного репозитория

Репозиторий будет публичным. Перед первым коммитом проверь вкладку Changes в GitHub Desktop:

- не добавляй `.env`, пароли, токены, API-ключи;
- не добавляй экспорт резервной копии LUMO или личные учебные данные;
- не добавляй `node_modules/` и `dist/` — они исключены через `.gitignore`;
- старый HTML-прототип исключён через `.gitignore`.

Данные IndexedDB не лежат в папке проекта и не публикуются вместе с исходниками. Но если в будущем добавятся секреты или серверные ключи, их нельзя помещать во frontend-код публичного репозитория.

## Шаг 1. Создать репозиторий

1. Открой GitHub в браузере и войди в аккаунт.
2. Нажми **New repository**.
3. Название можно выбрать `LUMO`.
4. Выбери **Public**.
5. Не добавляй README, `.gitignore` или License на сайте GitHub, потому что они уже есть в локальной папке.
6. Создай пустой репозиторий.

## Шаг 2. Подключить папку через GitHub Desktop

1. Открой GitHub Desktop.
2. Выбери **File → Add Local Repository**.
3. Укажи папку проекта LUMO (ту, где находятся `package.json` и `vite.config.ts`).
4. Если GitHub Desktop сообщает, что это не Git-репозиторий, выбери **create a repository** / **Create a repository here** и укажи эту же папку. Не создавай вложенную папку с ещё одним LUMO.
5. Проверь список Changes. Должны быть исходники, `package.json`, `package-lock.json`, конфигурация и документация. Не должно быть `node_modules`, `dist`, файлов резервных копий или `.env`.
6. Сделай первый commit, например `Prepare LUMO for GitHub Pages`.
7. Нажми **Publish repository** и убедись, что опция Private выключена.

## Шаг 3. Включить Pages

1. Открой репозиторий на GitHub.
2. Перейди в **Settings → Pages**.
3. В блоке **Build and deployment** выбери **GitHub Actions** как Source.
4. Перейди во вкладку **Actions**. Workflow `Deploy LUMO to GitHub Pages` должен запуститься после push в `main`.
5. Дождись зелёного статуса. Адрес сайта появится в **Settings → Pages** и в окружении `github-pages`.

Обычно URL project site будет `https://<username>.github.io/LUMO/`, если репозиторий назван `LUMO`.

## Шаг 4. Установка PWA в Windows

1. Открой опубликованный HTTPS-адрес в Chrome.
2. Дождись полной загрузки приложения и service worker.
3. Нажми значок установки в адресной строке или открой меню Chrome → **Трансляция, сохранение и отправка → Установить страницу как приложение** (названия пунктов могут отличаться).
4. Установи LUMO. После установки приложение появится в меню Пуск и сможет запускаться в отдельном окне.

## Как обновлять приложение

1. Вноси изменения в локальную папку проекта.
2. Проверь приложение локально: `npm install`, `npm run typecheck`, `npm test`, `npm run build`.
3. В GitHub Desktop проверь изменения и создай commit.
4. Нажми **Push origin**.
5. GitHub Actions автоматически соберёт и опубликует новую версию.
6. Благодаря `registerType: 'autoUpdate'` установленная PWA получит новую версию через service worker. Для проверки после публикации закрой и снова открой приложение.

## Важно о локальных данных и будущей синхронизации

Сейчас LUMO хранит данные в IndexedDB браузера. GitHub Pages размещает только статические файлы приложения и не переносит IndexedDB между компьютерами или браузерами. Публикация обновления не должна очищать базу данных.

Позже синхронизацию можно добавить отдельным этапом через backend (например, Supabase) и систему миграции/слияния локальных данных. До этого регулярно используй экспорт резервной копии в Settings. Не меняй origin опубликованного приложения без необходимости: браузерное хранилище привязано к origin.
