# LUMO — перенос и запуск в VS Code

## 1. Что находится в проекте

- `src/app` — корневое приложение и навигация.
- `src/domain` — типы и модели данных.
- `src/data` — IndexedDB, репозитории, резервное копирование.
- `src/features/planning` — страница занятия и таймер учебного времени.
- `src/features/practice` — редактор и механизм проверки упражнений.
- `src/features/packs` — импорт учебных пакетов.
- `src/features/progress` — аналитика прогресса.
- `src/styles` — оформление.
- `public` — статические ресурсы и иконки PWA.
- `vite.config.ts` — Vite и конфигурация PWA.

## 2. Требования

Установить Node.js LTS с npm. VS Code должен быть установлен отдельно. Интернет нужен для первоначальной установки npm-пакетов.

## 3. Открытие

1. Распаковать архив в постоянную папку, например `C:\Projects\LUMO`.
2. Открыть VS Code.
3. Выбрать **File → Open Folder** и указать папку `LUMO`.
4. Если VS Code предложит рекомендованные расширения, установить Prettier (остальные необязательны).
5. Открыть Terminal → New Terminal.

## 4. Установка и запуск

В терминале VS Code выполнить по очереди:

```bash
node -v
npm -v
npm install
npm run dev
```

Vite напечатает локальный адрес, обычно `http://localhost:5173/`. Открыть его в браузере. Не закрывать терминал, пока работает dev-сервер.

Для остановки сервера нажать `Ctrl+C`.

## 5. Проверка перед публикацией

```bash
npm run typecheck
npm run build
npm run preview
```

`npm run preview` запускает локальный просмотр production-сборки. PWA и Service Worker нужно проверять именно на production preview или HTTPS-хостинге, а не только в dev-режиме.

## 6. Важное о пользовательских данных

LUMO хранит данные в IndexedDB браузера. Они не лежат в папке проекта и не переносятся вместе с исходным кодом.

- Перед сменой браузера, профиля или origin экспортировать резервную копию из Settings.
- При переносе на другой компьютер сначала запустить приложение, затем восстановить JSON-копию через Settings.
- Не очищать данные сайта и не удалять IndexedDB без резервной копии.
- Данные привязаны к origin (протокол, домен и порт). `localhost:5173` и опубликованный сайт — разные хранилища.
- PWA-кеш не является резервной копией пользовательской базы.

## 7. Текущие ограничения и известные незавершённые задачи

- Проект подготовлен для VS Code, но в среде сборки не удалось установить npm-зависимости: запрос к реестру npm завершился тайм-аутом. Поэтому успешная TypeScript-проверка и production-сборка пока не подтверждены.
- Повторяющиеся занятия создаются на ограниченный горизонт (12 недель); автоматического продления серии ещё нет.
- Полный end-to-end прогон интерфейса, PWA установки и офлайн-режима ещё не выполнен.
- Необходимо проверить цикл резервного копирования на реальном браузере: экспорт → очистка тестового профиля → восстановление.
- Интерфейс местами использует простые браузерные `prompt`/`confirm` для ввода и подтверждений; это рабочая, но временная UX-реализация.
- Английская локализация не везде завершена.

## 8. Безопасная последовательность дальнейшей работы

1. Установить зависимости и добиться успешных `npm run typecheck` и `npm run build`.
2. Исправить все найденные ошибки сборки, не меняя структуру базы без миграции Dexie.
3. Проверить первый запуск: база пустая, демонстрационные записи отсутствуют.
4. Протестировать создание/редактирование/удаление занятия, отдельное повторение и будущую часть серии.
5. Протестировать таймер занятия после паузы, перезагрузки и сна компьютера.
6. Протестировать словарь, интервалы повторения, упражнения четырёх типов и тесты.
7. Протестировать импорт пакета, повторный импорт с личными изменениями и восстановление JSON-бэкапа.
8. Проверить PWA install, обновление Service Worker и работу без сети после первой загрузки.
9. После изменений схемы IndexedDB добавлять новую версию Dexie и миграцию. Не удалять базу для «починки» обновления.

## 9. Команды VS Code

В меню **Terminal → Run Task** доступны задачи `LUMO: install dependencies`, `LUMO: dev server`, `LUMO: typecheck` и `LUMO: production build`.
